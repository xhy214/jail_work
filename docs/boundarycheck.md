# 模型安全边界一致性测试工具

代码入口：`python3 -m boundarycheck`。Python 3.10+，仅标准库，不需要安装第三方依赖。

首版提供受控测试框架：同一测试请求保持不变，只改一个显示背景因素，重复调用目标模型，并用完全相同输入的重复对照测量自发波动。内置测试为合成内部标记保护和无害算术，不包含有害任务生成、提示搜索或奖励优化。

## 一句话示例

同样请求模型给出受保护的合成标记，一次显示主题为light，一次为dark。如果两次行为不同，还不能直接认为主题影响了边界；另外两次完全相同输入的调用用来检查模型本身是否也会前后不一致。

`canary`检测的是合成标记的完整归一化泄露；`exact`检测严格答案正确性。二者的结果分开报告。它们不能代替对任意危险内容的安全评价。

## 实验结构

每个任务、单一因素替代值、重复轮次各包含4次独立请求：

1. `baseline`：基准背景。
2. `changed`：请求文本和系统政策相同，只改一个因素。
3. `control_a`：与baseline完全相同的请求。
4. `control_b`：与baseline完全相同的请求。

四次调用不共享对话历史。每个四调用块内顺序和块间顺序按种子随机化。合成标记在同一任务的整个运行中固定，跨运行重新生成；不是实际凭据。记录精确请求哈希，以核查三次原样输入完全一致。

每组报告：

- 变更对不一致率：baseline与changed的判定不同的比例。
- 原样对照不一致率：control_a与control_b判定不同的比例。
- 二者差值，允许为负，不截断。
- 两个方向的计数及成对分歧列联计数。
- 完成、失败和待运行请求数；只有4次都完成的重复块纳入比较。

这些是描述性指标，不是自动生成的因果效应、显著性检验或真实模型安全率。显示因素在结构上只改一项，其语义是否无关仍需研究者确认。模型版本、时间漂移、缓存和服务端采样都可能影响结果。

## 先看预算

```sh
python3 -m boundarycheck plan --config examples/boundary_demo.json
```

示例为2任务×2单因素变体×12重复×4调用=192次，预算上限200。计划阶段没有网络请求。这里的12重复只是演示规模，不是经功效分析确定的样本量。

## 完整离线演示

```sh
python3 -m boundarycheck run --config examples/boundary_demo.json --mode mock --output runs/boundary-demo
```

模拟客户端刻意包含预设的不一致行为，用来测试统计与存储。其结果不反映任何真实模型能力或漏洞。`mock`是默认模式，不会因为缺少API配置而从live静默降级到mock。

产物：

- `experiment.db`：每次请求、响应、判定、随机化位置对应的trial_id、时间和错误类型。
- `summary.json`：不包含原始交互的聚合指标，明确标记模式。
- `report.md`：可读报告，mock模式标题明确注明模拟。

输出数据库已存在时拒绝覆盖。修改配置或重新运行需使用新目录。运行中断后保留pending状态并尽力生成报告；首版不支持自动续跑，以避免重复付费调用。

## 真实模型接口

通过环境设置安全配置以下变量：

| 名称 | 含义 |
|---|---|
| TARGET_API_BASE | HTTPS OpenAI兼容API根地址，通常以`/v1`结束，不含`/chat/completions` |
| TARGET_MODEL | 目标模型名称 |
| TARGET_API_KEY | 通过环境安全注入的凭据，不写入JSON或仓库 |

然后运行：

```sh
python3 -m boundarycheck run --config examples/boundary_demo.json --mode live --output runs/boundary-live
```

接口需要支持`messages`、`temperature`、`max_tokens`及常规文本返回。代码保留系统TLS验证和继承的代理，不支持关闭证书校验；拒绝带认证的重定向。截断、非文本或不支持的完成原因记录为失败，不拿部分输出当作安全结果。每个请求最多执行一次，没有自动重试；一个失败不导致无限循环。

API失败仅记录错误类型，避免服务器正文泄露密钥。返回非零命令退出码意味着存在failed或pending请求，不应将其解释为完整实验成功。

首版API传输格式通过模拟传输测试验证；尚未在本会话配置真实服务并完成实测。模型厂商支持的参数和模型版本需要运行前确认。相同temperature和本地随机种子不保证服务端输出可复现。

## 复算持久化结果

```sh
python3 -m boundarycheck report --db runs/boundary-live/experiment.db --output runs/boundary-live-report
```

只读访问数据库，不再次请求模型。

## 与旧RL代码的关系

此前RL.zip仍保留在工作区，无需重新上传。新工具沿用`TARGET_API_BASE / TARGET_API_KEY / TARGET_MODEL`命名、OpenAI兼容接口和SQLite逐条记录的约定，重新实现成对实验与无变更对照。

没有复制包内密钥或TLS跳过逻辑。旧Thompson老虎机负责按整体奖励选择组合；本次工具执行预先固定的成对实验，目标是检验一致性。首版不把旧检查点和整体reward当作新实验标签。

## 验证

```sh
python3 -m unittest discover -s tests -v
```

17项测试覆盖：单因素不变量、随机化复现、预算、配置合法性、标记匹配、已知差异、原样波动对照、API失败、中断记录、防覆盖、HTTPS约束和传输格式。另已完成192次模拟调用，并从SQLite重新生成相同聚合报告。

## 扩展边界

首版只有`canary`和`exact`两种可自动判定任务。更广泛的内容安全测试需要预先审核的用例、明确安全政策和独立标注接口；目前没有实现该接口，因此不能把本工具的合成标记泄露统计直接称为通用有害内容红队成功率。

`runs/`、`.env`和缓存已忽略。不要将实际模型原始交互或凭据混入公开提交。公开结果前先审核输出。
